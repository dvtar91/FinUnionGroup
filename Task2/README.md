# Задание 2. Мастер-системы и потоки данных

**Цель задания:** определить мастер-системы для ключевых сущностей, описать владение данными, построить диаграмму потоков данных и опишите управление потоками данных.

## Конкретные задачи

**1. Определите мастер-системы**

Для каждой ключевой сущности определите мастер-систему в промежуточном и целевом состояниях.

Различайте:

* систему-источник, где данные сейчас хранятся физически;
* систему, где данные впервые появляются;
* мастер-систему с эталонными данными, откуда они должны распространяться в другие системы;
* MDM / Customer Hub — компонент для ведения золотой записи клиента или справочников, если он нужен.

Не назначайте MDM мастер-системой для всех сущностей автоматически. Например, для клиентских и справочных данных MDM годится, а счета, транзакции и финансовые операции должны оставаться в профильных банковских системах.

При определении мастер-систем используйте результаты маппинга BIAN из задания 1: покажите, какие BIAN-домены помогают определить границы владения клиентскими, счётными, платёжными, карточными и кредитными данными.

Пример:

|Сущность|Источники As-Is|Мастер-система на 3 месяца|Целевая мастер-система|Связь с BIAN|Обоснование|
|--------|---------------|--------------------------|----------------------|------------|-----------|
|Клиент|FU CRM, RB CRM|MDM Customer Hub|MDM|Party Data Management|Нужна золотая запись клиента|

**2. Опишите правила владения данными**

|Сущность|Что указать|
|--------|-----------|
|Data Owner|Бизнес-владелец данных|
|Data Steward|Ответственный за качество данных|
|Producer|Система или команда, создающая данные|
|Consumer|Система-потребитель|
|Правила изменения|Кто может менять данные|
|Правила качества|Обязательные проверки|

**3. Постройте диаграмму потоков данных**

Создайте диаграмму потоков данных (Data Flow Diagram) для промежуточного состояния через три месяца (уровень 0 — контекстная диаграмма).

На диаграмме отразите основные системы из ландшафта As-Is и целевые компоненты, которые нужны для промежуточного состояния.

Минимальный набор элементов:

* CRM FinUnion
* CRM RetailBank
* Core Banking FinUnion
* Card Processing FinUnion
* Core Banking RetailBank
* Card Processing RetailBank
* Loan System FinUnion
* Loan System RetailBank
* MDM Customer Hub
* Integration Layer
* DWH
* BI
* DataHub или каталог данных
  
Регуляторную отчётность покажите как внешнего потребителя или поток выгрузки из DWH.  

DFD должна показывать, как данные проходят между системами и где выполняются операции, посредством действий:

* Create
* Read
* Update
* Delete
* Enrich
* Validate
* Aggregate

**4. Опишите управление потоками данных**

Создайте таблицу управления потоками данных со следующей структурой (потоки определите самостоятельно):

|Источник|Приёмник|Сущность|Действие|Формат|Частота|Тип обмена|SLA|Владелец|Контроль качества|
|--------|--------|--------|--------|------|-------|----------|---|--------|-----------------|
|RB|CRM|MDM|Клиент|Create/Update/Deduplicate|JSON|Near real-time|Async|5 мин|Data Office|Проверка дублей|

**5. Опишите проблемные зависимости**

Опишите минимум пять зависимостей или рисков на уровне данных.

Пример:

|Проблема|Последствие|
|--------|-----------|
|Разные идентификаторы клиента|Невозможно построить единый профиль|

В результате структура директории Task2 должна быть такой:

```
Task2/
├── README.md
├── master-systems.md
├── data-ownership.md
├── data-flows.md
├── data-flow-management.md
├── data-dependencies.md

```

Файл data-flows.md должен содержать описание основных потоков данных между системами:

* источник;
* приёмник;
* передаваемые сущности;
* тип действия с данными;
* режим обмена: синхронный, асинхронный, batch, streaming, CDC;
* краткое обоснование, зачем нужен поток.

Файл data-flow-management.md должен содержать таблицу управления потоками:

* SLA;
* владелец потока;
* контроль качества;
* формат данных;
* частота обмена;
* требования к безопасности;
* способ мониторинга.
