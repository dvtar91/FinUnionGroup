# Сопоставление сущностей с референсной моделью BIAN

| Сущность | BIAN‑область (Service Domain) | Как BIAN помогает |
|----------|------------------------------|-------------------|
| Клиент | **Party Data Management (PDM)** | Унифицирует идентификацию клиента, гарантирует единую «золотую запись», упрощает согласование клиентских профилей между FinUnion и RetailBank |
| Счёт | **Current Account (CA)** | Стандартные модели счёта, операции, балансы; единые API‑контракты позволяют построить шлюз «Account API» |
| Карта | **Card Management (CM)** | Описывает жизненный цикл карт, статусы, тарифы, согласованную модель токенизации |
| Кредит | **Loan Management (LM)** | Содержит бизнес‑правила расчёта, графика погашения, реструктуризаций – удобно для консолидированных кредитных портфелей |
| Договор | **Product Fulfilment (PF)** | Описывает привязку продукта к клиенту, статусы, даты, условия |
| Транзакция | **Payments Execution (PE)** | Унифицирует типы операций, схемы маскирования, контроль двойных списаний |
| Продукт | **Product Management (PM)** | Справочник продуктов, версии, тарифы – позволяет синхронизировать каталоги между двумя банками |
| Обращение | **Customer Contact (CC)** | Структурирует каналы взаимодействия, типы запросов, SLA‑метрики |
| Контрагент | **Counterparty Management (CMG)** | Единый справочник контрагентов, анти‑фрод правила, AML‑проверки |
| Тариф/Комиссия | **Pricing Management (PRM)** | Управление ценовой политикой, версии тарифов, согласование в разных регионах |
| Отделение/Канал | **Channel Management (CHM)** | Описание физических и цифровых каналов, их доступности, клиентских сегментов |
| Документ | **Document Management (DM)** | Хранение и контроль доступа к юридическим документам, подписи, версии |
